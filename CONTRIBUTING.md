# Contributing to Utsav

Thank you for helping build Utsav — an AI-assisted event planner where **the AI proposes,
the engine validates, and the user decides**. This guide covers how to set the project up
and the conventions that keep it auditable. Security-sensitive disclosures go through
[SECURITY.md](SECURITY.md), not pull requests.

## Setup

```bash
npm ci          # exact dependency tree from the lockfile
npm run dev     # Vite dev server + local API bridge
npm test        # unit/integration tests (vitest)
npm run e2e     # real-browser E2E against the production build (Playwright)
```

Node 22 or newer. Copy `.env.example` to `.env` only if you need the live AI routes;
the app is fully functional without any key (deterministic built-in fallbacks answer,
and they say so).

## The quality gates

`npm run check` runs format, lint, typecheck, architecture, unused-code and tests with
enforced coverage thresholds. CI additionally runs the production build, the bundle-size
budget, the runtime dependency audit, the secret scan, the repository-size check and the
full E2E suite — the same gate set documented in the README. A pull request is reviewable
only when every gate is green; no gate may be weakened or skipped to make a change pass.

## Conventions

**Architecture.** `src/engine/` is pure domain logic (no React, no DOM); `src/state/`
holds the store and persistence; `src/ui/` renders and interacts; `api/` are serverless
functions. dependency-cruiser (`.dependency-cruiser.cjs`) enforces the layering — UI may
import the engine, never the reverse, and there are no cycles. Keep domain decisions in
the engine and rendering concerns in components.

**File size.** Source files under `src/` and `api/` stay at 250 lines or fewer
(`tests/quality/hygiene.test.ts` enforces it). Split at meaningful seams — a module
should have one reason to change — and never carve code artificially.

**TypeScript.** Strict mode with `noUncheckedIndexedAccess` and
`exactOptionalPropertyTypes`. `any`, `@ts-ignore` and `@ts-nocheck` are banned; narrow
types instead. ESLint uses `typescript-eslint` strictTypeChecked plus
`eslint-plugin-react-hooks` (Rules of Hooks are law: no conditional hook counts) and
`eslint-plugin-jsx-a11y`.

**Money.** All amounts are integer minor units. Currency decimal places come from
`currencyExponent()` in `src/engine/money.ts` — never from an inline table. Financial
calculations live only in the engine.

**React.** Every hook call must be unconditional and in the same order on every render
(wrapper components resolve data; children own the hooks). Effects synchronise external
systems; they do not derive state. `tabIndex={0}` is used only to make scrollable
regions keyboard-accessible; positive `tabIndex` values are banned.

**Server logging.** `api/` logs use fixed string messages only — never interpolate
prompts, keys, user text or request data. Typed error codes (`AI_HTTP_*`,
`AI_DAILY_CAP`, …) carry the machine-readable detail.

**Tests.** Behaviour changes need tests. New modules get direct tests for their public
behaviour; the 250-line cap and the hygiene rules are themselves tested. Do not delete
or weaken existing tests, and keep coverage at or above the recorded thresholds.

**Commits.** Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`,
`chore:`), one logical change per commit. Work on feature branches; `main` changes only
through reviewed pull requests — never force-push.

**Docs.** `docs/METRICS.md` is generated by `node scripts/gen-metrics.mjs` from real
runs — never typed by hand. Recorded evidence files under `docs/evidence/` and
`e2e/evidence/` are append-only records; update them only by re-running the recording
scripts.
